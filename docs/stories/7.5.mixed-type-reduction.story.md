# USER-7.5 — Ridurre `mixed` dove possibile

## User story

Come **maintainer del modulo User**,
voglio **che `mixed` compaia solo dove il valore è genuinamente polimorfico o
imposto da una firma vendor**,
così che **PHPStan possa inferire tipi reali invece di rinunciare, e i bug di
narrowing (vedi `7.4`) siano più rari**.

## Contesto

Convenzione di progetto (root `CLAUDE.md`): "cerchiamo di non usare mixed,
quando lo troviamo cerchiamo di sostituirlo con qualcosa di adeguato". Non è
il gate `typeCoverage.paramTypeCoverage` di `7.4` (quello impone un tipo
*qualsiasi*, `mixed` incluso, e non lo conta — vedi memoria
`type-coverage-non-conta-mixed`): qui l'obiettivo è la qualità del tipo, non
la sua sola presenza.

**Vincolo di sessione**: al momento di iniziare, `git status` sul repo del
modulo mostrava 1212 file modificati non committati (line-ending
renormalization da un `.gitattributes` cambiato + lavoro applicativo reale di
altre sessioni concorrenti — un file, `README.md`, aveva persino marker di
merge non risolti). Per non rischiare di sovrascrivere lavoro altrui in corso
(vedi memoria `multi-agent-same-repo-race` e l'incidente reale dello stesso
giorno documentato in
`docs/chat/user-profile-instanceof-two-independent-fixes.md`), il lavoro di
questa story si è limitato ai soli file **non** già sporchi nel working tree.

## Cosa è stato fatto

Censimento: 194 file / 416 occorrenze di `mixed` in `Modules/User`, di cui 91
file in stato pulito (git status). Tra questi, 13 avevano type-hint nativo
(`mixed $x` / `: mixed`), gli altri solo `mixed` in docblock.

Modificati 3 file (tutti a zero `mixed` residuo):

1. `app/Actions/Shield/ResolveSuperAdminConfigurationAction.php`
2. `app/Actions/Shield/ResolveFilamentUserConfigurationAction.php`
3. `app/Filament/Clusters/Passport/Resources/OauthRefreshTokenResource/Pages/ViewOauthRefreshToken.php`

Dettaglio tecnico e motivazione dei restanti file lasciati invariati (con
motivazione per ciascuna categoria): vedi `docs/coverage.md`, sezione
"Riduzione `mixed` — 2026-09-04".

## Acceptance criteria

- [x] AC1 — Nessuna modifica a `phpstan.neon`.
- [x] AC2 — `./vendor/bin/phpstan analyse Modules/User --no-progress` resta a
      0 errori (era già 0 prima).
- [x] AC3 — Nessun `@phpstan-ignore` introdotto.
- [x] AC4 — Ogni file toccato ha un `mixed` in meno rispetto a prima (in
      questo caso: zero residuo).
- [ ] AC5 — Copertura 100% dei 194 file iniziali — esplicitamente NON
      raggiunto (best-effort "dove possibile" da istruzioni task, e ~103 file
      erano fuori scope per lo stato sporco del working tree). Vedi `7.4` per
      il lavoro residuo full-tree.

## Owned file/module scope

Solo i 3 file elencati sopra, dentro `laravel/Modules/User/`.

## Testing

  → 0 errori prima e dopo.
- `tools/phpmd.sh` sui 3 file singolarmente (il run sull'intero modulo va in

`git checkout`/`reset` su quei file per "ripulire": potrebbe distruggere
lavoro reale non ancora salvato altrove (vedi memoria
`git-forward-only`).

## Follow-up 2026-09-21 — declare blade/lang (non mixed)

**Perché**: il tipo è il contratto anche sulle viste. `declare(strict_types=1)` va
in testa a ogni `.php` / `.blade.php`. Questo follow-up **non** riduce `mixed`.

**Come (blade)**: prepend del blocco, mai replace dei primi byte (un replace cieco
ha già mangiato `@extends` / `<!DOCTYPE` in altri moduli).

```php
<?php

declare(strict_types=1);

?>
```

| File | Esito |
|------|--------|
| `lang/it/.php` | già con declare — skip |
| `lang/lang/it/.php` | già con declare — skip |
| 9 blade con markup integro | prepend |
| `widgets/auth/register-widget.blade.php` | prepend su frammento `</div>` (non ricostruito) |

Non toccati: `AdminPanelProvider.php`, lock story 9.2 / 10.3, HTTP SuperAdmin/Team/Change/Socialite Buttons, conversioni Livewire, `mixed`.

Gate: `php -l` su tutti i path in scope → 0 errori.

Campagna: [strict-types-mixed-campaign.md](../../../../../docs/chat/strict-types-mixed-campaign.md)

## Follow-up — riduzione `mixed` evidenti (widget)

**Perché**: `mixed` sul parametro spegne PHPStan per tutta la funzione. Dove il
chiamante ha una shape nota, il contratto deve dirla.

### Sostituiti

- `RegistrationWidget::normalizeFormSchema(mixed $schema)` → `array`.
  `getFormSchemaWidget()` è documentato come `array` di `Component`; il
  `is_array` sta sul caller (`class-string` dinamico). `AdminPanelProvider`
  non toccato.
- `UserTypeRegistrationsChartWidget::parseFilterDate(mixed $value)` →
  `string|int|null` (DatePicker / timestamp). Narrowing `is_string`/`is_int`
  estratto in `parseFilterDateFromFilters` per non alzare la CC di `getData()`.

### Lasciati `mixed` (motivato)

- Closure `Collection::map(fn (mixed $value)` su Trend: Larastan è spento in
  `phpstan.neon`; senza generic la collection è eterogenea. Non restringere
  sotto la firma vendor.
- `array<string, mixed>` su fill/state del form: bag Filament.

### Gate

- `php -l` + PHPStan (max da neon, no `--level`) sui due widget: 0 errori.
- PHPMD: ChartWidget pulito; `RegistrationWidget` `MissingImport` su
  `\RuntimeException` preesistente (riga `register()`, non toccata).
- Pest correlato `UserGapAttackCoverageTest` filtro widget: fatal in
  `PasswordExpiredWidget.php` (`TransTrait` importato due volte) — file non
  in scope, lavoro concorrente. Non è questo diff.
